## Loading configuration

The control plane reads JSON, JSON5, JSONC or YAML files, then applies environment variables on top.

- **Files.** Pass `--config` with a file or a directory; files in a directory are merged. Repeat `--config` to merge several paths in order. Without `--config`, the control plane loads `/etc/rivet` if it exists.
- **Environment variables.** Prefix a setting with `RIVET__` and separate each level with `__`. For example, `depot.log_directory` is `RIVET__DEPOT__LOG_DIRECTORY`.

```bash
rivet-engine --config /etc/rivet/config.json
```

Unknown settings are an error, so a typo stops the control plane at startup instead of being ignored.

## Required settings

| Setting | Purpose |
| --- | --- |
| `auth.admin_token` | Your Rivet token, the credential nodes and your backend use. The control plane refuses to start without it. |
| `depot.log_directory` | The instance's disk. The directory must already exist. See <SelfHostLink to="control-plane/storage">Storage</SelfHostLink>. |
| `object_storage.primary` | The bucket. The default keeps data in memory and loses it on restart. See <SelfHostLink to="control-plane/storage">Storage</SelfHostLink>. |
| `api_peer.advertise_address` | The `host:port` other instances use to reach this one on port `6421`. Required when more than one instance runs. |

## Rivet token

Your Rivet token is the `auth.admin_token` value. It works in every namespace. Generate one with `openssl rand -hex 32` and keep it on your backend.

Clients pass it as a bearer token, or inside the endpoint URL:

```bash
export RIVET_ENDPOINT="https://default:$RIVET_TOKEN@rivet.example.com"
```

Use it to issue scoped tokens for browser clients, and keep the Rivet token itself out of them. See [Scoped Tokens](/docs/jwt).

## Crash reports

The control plane sends crash reports to Rivet by default. Turn them off with `"telemetry": { "enabled": false }` or `RIVET__TELEMETRY__ENABLED=false`.
