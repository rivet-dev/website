Standing one up is four decisions:

1. **A platform to run the container on.** Pick from the guides below.
2. **A storage backend.** File system for a single node, PostgreSQL for multi-node. See <SelfHostLink to="control-plane/storage">Storage</SelfHostLink>.
3. **An admin token**, so the API and dashboard are not open. See <SelfHostLink to="control-plane/configuration">Configuration</SelfHostLink>.
4. **A reverse proxy that tolerates long-lived WebSockets.** See <SelfHostLink to="control-plane/ports">Ports</SelfHostLink>.

## Trying it locally

One command, no persistence, useful only for a look around:

```bash
docker run -p 6420:6420 rivetdev/engine
```

Open `http://localhost:6420/ui` for the dashboard. For anything you intend to keep, start from a platform guide instead: this container writes to a path inside itself that disappears when the container does.
