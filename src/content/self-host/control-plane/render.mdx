Render runs one control plane instance with a Render persistent disk. Use it to try Rivet on a managed platform. For production, run three or more instances on <SelfHostLink to="control-plane/kubernetes">Kubernetes</SelfHostLink> or <SelfHostLink to="control-plane/vm">VMs</SelfHostLink>.

## Requirements

- A [Render account](https://render.com)
- An object storage bucket, such as S3.

## Steps

<Steps>

<Step title="Create the service">

Create a Web Service from the image `rivetdev/engine:next` with the Docker command `--config /etc/rivet`.

</Step>

<Step title="Add a disk">

Add a persistent disk mounted at `/var/lib/rivet/log`. A service with a disk runs one instance.

</Step>

<Step title="Set the variables">

```bash
RIVET__AUTH__ADMIN_TOKEN=<openssl rand -hex 32>
RIVET__DEPOT__LOG_DIRECTORY=/var/lib/rivet/log
RIVET__DEPOT__AUTO_PROVISION_TABLETS=1
RIVET__DEPOT__BALANCING__ENABLED=false
RIVET__OBJECT_STORAGE__PRIMARY__S3__BUCKET=my-rivet-bucket
RIVET__OBJECT_STORAGE__PRIMARY__S3__REGION=us-east-1
RIVET__OBJECT_STORAGE__PRIMARY__S3__ACCESS_KEY_ID=...
RIVET__OBJECT_STORAGE__PRIMARY__S3__SECRET_ACCESS_KEY=...
```

See <SelfHostLink to="control-plane/storage">Storage</SelfHostLink> for other object storage backends.

</Step>

<Step title="Expose port 6420 and verify">

Set the service port to `6420`, then:

```bash
curl https://<service>.onrender.com/health
```

```json
{"runtime":"engine","status":"ok","version":"3.0.0-preview.1",...}
```

</Step>

</Steps>
