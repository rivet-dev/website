---
title: "Rivet Services"
description: "Self-host Durable Streams and agentOS VMs, with Actor data persisted by your Rivet control plane."
---

Rivet Services is a container of prebuilt Rivet Actors that provide services such as Durable Streams and agentOS VMs. Think of it as Rivet's equivalent of managed services built on Cloudflare Durable Objects: Services runs the application logic, while your control plane handles scheduling and persistence.

Run it alongside your control plane when you self-host these services. On Rivet Cloud it is already running.

## Services included

### Durable Streams

Real-time streams with durable history, served over HTTP at `http://<host>:8642/durable-streams/v1/stream/<path>`. Each stream is its own Rivet Actor, which stores the stream's history and metadata. See [Durable Streams](/durable-streams/docs/).

### agentOS

Hosted agentOS VMs, created and called through your control plane. See [agentOS](/agentos/docs/quickstart-hosted/).

## Persistence

**Service data is stored by the control plane, not on the Services container's filesystem.** Durable Streams history and agentOS VM data use the same durable Actor storage as your own Rivet Actors. You do not need a separate database, bucket, or persistent volume for the Services container.

Each Actor has a durable volume. The control plane persists writes to its log disks before acknowledging them and moves data to object storage in the background. Restarting or replacing Services does not delete persisted stream history; the replacement connects to the same control plane and namespace to load the existing Actors.

What you need to retain depends on your control plane setup:

| Setup | Where service data lives | What to preserve |
| --- | --- | --- |
| <SelfHostLink to="control-plane/docker-compose">Docker quickstart</SelfHostLink> | The control plane's `rivet-log` and `rivet-objects` Docker volumes | Both volumes, including when recreating the control plane container. Do not run `docker compose down -v`, which deletes named volumes. |
| Production | Each control plane instance's persistent log disk and the cluster's object storage bucket | The log disks and bucket. Configure durable storage and backups on the control plane, not on Services. |

<Warning>
Services is only as durable as the control plane's storage configuration. The default in-memory object storage backend loses Actor data when the control plane restarts. Use the persistent volumes from the Docker quickstart for local testing, and a bucket plus persistent log disks in production. See <SelfHostLink to="control-plane/storage">Storage</SelfHostLink> and <SelfHostLink to="control-plane/backups">Backup & Restore</SelfHostLink>.
</Warning>

## Run it

You need a running control plane and its Rivet token. See <SelfHostLink to="control-plane">Control Plane</SelfHostLink> to set one up.

<Steps>

<Step title="Create the services node pool">

```bash
curl -X PUT "http://localhost:6420/pools/services?namespace=default" \
  -H "Authorization: Bearer $RIVET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{}'
```

</Step>

<Step title="Start Services">

<Tabs>

<Tab title="Docker run">

```bash
docker run -d --name rivet-services \
  --add-host=host.docker.internal:host-gateway \
  -e RIVET_ENDPOINT=http://host.docker.internal:6420 \
  -e RIVET_TOKEN="$RIVET_TOKEN" \
  -e HOST=0.0.0.0 \
  -p 8642:8642 \
  rivetdev/services:0.2.5
```

</Tab>

<Tab title="Docker Compose">

Add this service next to `rivet` in the Compose file from the <SelfHostLink to="control-plane/docker-compose">Docker Compose</SelfHostLink> guide:

```yaml
  rivet-services:
    image: rivetdev/services:0.2.5
    ports:
      - "8642:8642"
    environment:
      RIVET_ENDPOINT: "http://rivet:6420"
      RIVET_TOKEN: "${RIVET_TOKEN}"
      HOST: "0.0.0.0"
    depends_on:
      - rivet
    restart: unless-stopped
```

</Tab>

</Tabs>

</Step>

<Step title="Check that it works">

<Tabs>

<Tab title="Durable Streams">

```bash
curl -X PUT -H 'content-type: application/json' \
  --data '[{"message":"hello"}]' \
  http://localhost:8642/durable-streams/v1/stream/demo

curl 'http://localhost:8642/durable-streams/v1/stream/demo?offset=-1'
```

The read returns `[{"message":"hello"}]`.

</Tab>

<Tab title="agentOS">

Create a VM in the `services` pool, then run a command in it:

```bash
VM_ID=$(curl -s -X PUT "http://localhost:6420/actors?namespace=default" \
  -H "Authorization: Bearer $RIVET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"agentOS","key":"my-vm","pool":"services","crash_policy":"sleep"}' \
  | jq -r .actor.actor_id)

curl "http://localhost:6420/gateway/$VM_ID/action/v1.process.run" \
  -H "x-rivet-token: $RIVET_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"args":[{"command":"sh","args":["-c","echo hello"],"options":{"captureStdio":true}}]}'
```

The response includes `"stdout":"hello\n"`.

</Tab>

</Tabs>

</Step>

</Steps>

## Configuration

| Variable | Description |
| --- | --- |
| `RIVET_ENDPOINT` | Where Services reaches the control plane. |
| `RIVET_TOKEN` | Your Rivet token. |
| `RIVET_NAMESPACE` | The namespace to join. Defaults to `default`. |
| `HOST` | Address to listen on. Set `0.0.0.0` in a container. |
| `PORT` | Port to listen on. Defaults to `8642`. |

## Local development

RivetKit starts Services automatically during local development when you run your application with its managed local control plane. Without RivetKit, `npx @rivet-dev/services dev` starts a local control plane and Services together.
