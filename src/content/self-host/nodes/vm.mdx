---
title: "VM & Bare Metal"
description: "Run Rivet nodes on a Linux VM or bare metal host."
---

Your process runs as a node: it opens a connection out to the control plane on startup. The host needs no public URL, only outbound network access.

## Requirements

A namespace and a node pool created with `PUT /pools/{pool}` (see [Nodes & Node Pools](/docs/nodes#quickstart)). In local development, RivetKit creates the `default` pool for you.

- A Linux host with SSH access and Node.js installed. Hetzner, DigitalOcean, Linode, EC2, and bare metal all work the same way.
- A running <SelfHostLink to="control-plane">control plane</SelfHostLink>

## Steps

<Steps>

<Step title="Upload your build">

Build locally, then copy the output somewhere readable by the service user:

```bash
scp -r ./dist user@server:/opt/rivet-node
```

</Step>

<Step title="Create the systemd unit">

`TimeoutStopSec` is the important line. Each Rivet Actor gets up to 15 seconds to save its state, so allow a minute.

```ini /etc/systemd/system/rivet-node.service
[Unit]
Description=Rivet Node
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/rivet-node
ExecStart=/usr/bin/node server.js
Restart=on-failure
TimeoutStopSec=60
Environment=RIVET_ENDPOINT=<your-rivet-endpoint>

[Install]
WantedBy=multi-user.target
```

The endpoint value is described in <SelfHostLink to="nodes">Deploy Nodes</SelfHostLink>. For secrets, prefer `EnvironmentFile=` pointing at a root-owned file over inline `Environment=` lines.

</Step>

<Step title="Start the service">

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now rivet-node.service
```

</Step>

<Step title="Verify">

```bash
systemctl is-active rivet-node.service
```

Expect `active`. Call one of your Rivet Actors to confirm it responds.

</Step>

</Steps>

## Scaling

There is no autoscaler on a bare host. Nodes are interchangeable, so capacity is added by running the same unit on more hosts, each with its own `RIVET_ENDPOINT`. They all join the same pool and start serving Rivet Actors. To autoscale instead, move the node to a platform that has one, such as <SelfHostLink to="nodes/kubernetes">Kubernetes</SelfHostLink> or <SelfHostLink to="nodes/aws-ecs">ECS</SelfHostLink>.

Running two units on one host works but shares the host's CPU and memory, so it adds concurrency rather than capacity.

## Operating

Restart after deploying a new build or changing environment variables:

```bash
sudo systemctl restart rivet-node.service
```

Follow logs while debugging:

```bash
sudo journalctl -u rivet-node.service -f
```
