---
title: "Docker Compose"
description: "Run Rivet nodes with Docker Compose."
---

Your container runs as a node: it opens a connection out to the control plane on startup. It needs no published port.

## Requirements

A namespace and a node pool created with `PUT /pools/{pool}` (see [Nodes & Node Pools](/docs/nodes#quickstart)). In local development, RivetKit creates the `default` pool for you.

- Docker with the Compose plugin
- A running <SelfHostLink to="control-plane">control plane</SelfHostLink>

## Steps

<Steps>

<Step title="Package your app">

```dockerfile
FROM node:24-slim
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
CMD ["node", "server.js"]
```

`CMD` invokes the binary directly rather than `npm start`, so the process receives `SIGTERM` and can drain.

Rivet requires Node.js 22 or newer.

</Step>

<Step title="Add the service">

`stop_grace_period` matters here. Each Rivet Actor gets up to 15 seconds to save its state, and Compose's default of 10 seconds can cut them off.

```yaml
services:
  my-app:
    build: .
    environment:
      RIVET_ENDPOINT: "${RIVET_ENDPOINT}"
    stop_grace_period: 60s
    restart: unless-stopped
```

The endpoint value is described in <SelfHostLink to="nodes">Deploy Nodes</SelfHostLink>. Put it in a `.env` file next to the Compose file and keep it out of version control.

</Step>

<Step title="Run alongside a self-hosted control plane">

When both halves live in the same Compose file, the node reaches the control plane by service name over the Compose network:

```yaml
  my-app:
    build: .
    environment:
      RIVET_ENDPOINT: "http://default:${RIVET_TOKEN}@rivet:6420"
    depends_on:
      - rivet
    stop_grace_period: 60s
    restart: unless-stopped
```

See <SelfHostLink to="control-plane/docker-compose">the control plane guide</SelfHostLink> for the other half of this file.

</Step>

<Step title="Start it">

```bash
docker compose up -d
```

</Step>

<Step title="Verify">

```bash
docker compose ps
```

The service should be `running`. Call one of your Rivet Actors to confirm it responds.

</Step>

</Steps>

## Scaling

Compose has no autoscaler. Nodes are interchangeable, so `docker compose up -d --scale my-app=3` adds replicas that all join the same pool, but they share one host's CPU and memory. For capacity beyond a single host, or for autoscaling, move to <SelfHostLink to="nodes/kubernetes">Kubernetes</SelfHostLink> or <SelfHostLink to="nodes/aws-ecs">ECS</SelfHostLink>.

Keep `stop_grace_period: 60s` on every replica. Scaling down cuts actors off otherwise.
