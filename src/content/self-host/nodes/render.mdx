Your service runs as a node: it opens a connection out to the control plane on startup. It needs no public URL, so a Render Background Worker suits it as well as a Web Service.

## Requirements

A namespace and a node pool created with `PUT /pools/{pool}` (see [Nodes & Node Pools](/docs/nodes#quickstart)). In local development, RivetKit creates the `default` pool for you.

- A [Render account](https://render.com)
- A GitHub repository containing your app
- A running <SelfHostLink to="control-plane">control plane</SelfHostLink>

## Steps

<Steps>

<Step title="Add the service">

```yaml render.yaml
services:
  - type: worker
    name: rivet-node
    runtime: docker
    dockerfilePath: ./Dockerfile
    plan: starter
    envVars:
      - key: RIVET_ENDPOINT
        sync: false
```

`type: worker` is a Background Worker: no public URL and no HTTP port, which is exactly what a node needs. Use `type: web` instead only if the same service also serves your application traffic.

`sync: false` keeps the value out of the blueprint so you set it as a secret in the dashboard.

</Step>

<Step title="Set the endpoint">

Set `RIVET_ENDPOINT` on the service in the Render dashboard. The value is described in <SelfHostLink to="nodes">Deploy Nodes</SelfHostLink>.

</Step>

<Step title="Deploy">

Push to the connected branch, or click **Manual Deploy**.

</Step>

<Step title="Verify">

The service log should show the node connecting. Call one of your Rivet Actors to confirm it responds.

</Step>

</Steps>

## Scaling

Nodes are interchangeable, so instance count can be raised, or driven by Render's autoscaling on a CPU target. Target 60% CPU, matching the rest of the guides. Nothing needs re-registering; new instances dial out and start serving Rivet Actors. See [Render's scaling docs](https://render.com/docs/scaling).

Scaling in is bounded by the drain below, so an instance being removed keeps serving its actors well past the point Render stops routing to it.

## Graceful shutdown

Each Rivet Actor gets up to 15 seconds to save its state when the process stops. Set Render's shutdown delay to 60 seconds, plan deploys so a new instance is up before the old one goes away, and keep the process itself signal-aware: a wrapper such as `npm start` becomes PID 1 and swallows `SIGTERM`. Invoke the binary directly, or use `dumb-init` or `tini`.
