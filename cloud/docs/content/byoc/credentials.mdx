After Rivet confirms your deployment is ready, run these commands from your extracted bundle's root directory. The same commands work for AWS and Google Cloud.

## Requirements

- Your deployment bundle and access to its Terraform state
- [Terraform](https://developer.hashicorp.com/terraform/install) 1.9 or newer, below 2.0, and [Python](https://www.python.org/downloads/) 3.9 or newer
- An authenticated [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) or [Google Cloud CLI](https://cloud.google.com/sdk/docs/install), with permission to read the admin secret and access the cluster
- [kubectl](https://kubernetes.io/docs/tasks/tools/) and permission to forward pod ports
- For Google Cloud: the [GKE authentication plugin](https://cloud.google.com/kubernetes-engine/docs/how-to/cluster-access-for-kubectl)

## Manual access

### Get your admin token

1. Find the admin-secret reference in your Terraform deployment outputs
2. Open that secret in AWS Secrets Manager or Google Cloud Secret Manager
3. Copy its value—the admin token, not the operator token used in `RIVET_BYOC_OPERATOR_TOKEN`

### Open the dashboard

1. Open your deployment endpoint with `/ui` appended, or create a local tunnel:

   Configure `kubectl` access to your cluster, then run:

   <CodeSnippet file="examples/docs/byoc/dashboard-port-forward.sh" />

   Replace `<cluster-context>` with your Kubernetes context and `rivet` with your `kubernetes_namespace` if you changed the default. Open [http://127.0.0.1:6420/ui](http://127.0.0.1:6420/ui) and keep the command running.

2. Sign in with your admin token

## Provision new tokens

Create tokens with the permissions your application needs. See [Role-Based Access Control](/actors/self-host/control-plane/rbac).
