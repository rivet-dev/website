## Durability

An agent keeps nothing important in memory. Its session and the id of its sandbox live in the Actor's own [SQLite database](/actors/docs/sqlite), so the agent can sleep while idle, and a crash or deploy does not lose the conversation.

### What is stored

The Actor's SQLite database holds three things:

| What | Contents | Written |
| --- | --- | --- |
| Session | The session id, working directory, and settings. | When the session is first created, and when settings change. |
| Entries | One row per session entry, in order. | As the agent appends each entry: every message, tool call, and tool result. |
| Sandbox | The sandbox provider's name and the sandbox id. | As soon as the provider creates the sandbox. |

### On wake

The first action after the Actor wakes opens the session:

1. It reads the session and every entry from SQLite and rebuilds the session from them.
2. It reconnects to the stored sandbox by id. If the provider reports that the sandbox is gone, it creates a new one. See [Sandboxes](/agents/docs/sandboxes#how-the-sandbox-is-managed).
3. It restores the saved settings and the saved model, if that model is still allowed. Otherwise it falls back to the agent's configured model.

Clients do not have to do anything. Calling any action on the same key resumes the same conversation.

### On sleep and destroy

- **Sleep.** The Actor aborts a run in progress, closes the session, and asks the provider to suspend the sandbox. Every entry written before the abort is kept.
- **Crash.** Entries are written as they happen, so the session reopens from the last entry written before the crash.
- **Destroy.** The Actor closes the session and asks the provider to delete the sandbox.
