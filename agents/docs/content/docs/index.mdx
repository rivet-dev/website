---
title: "Agents"
description: "Run a coding agent as a durable Rivet Actor, with its tools in a separate sandbox."
---

Each agent on Rivet is one [Rivet Actor](/actors/docs). You define the agent once, and every key you call it with gets its own Actor, session, and sandbox.

- **The agent loop runs in the Actor.** Model calls, retries, and the conversation run in your backend, next to your application code, where you control credentials, permissions, and logging.
- **Tools run in a separate sandbox.** File and shell tools call into a sandbox such as agentOS, E2B, or Daytona. Nothing the agent runs executes on your worker, and your provider keys never enter the sandbox.
- **The session survives sleep and restarts.** The Actor stores the session in its SQLite database and restores it when it wakes, so an idle agent can sleep and a crash or deploy does not lose the conversation.

Start with the [Pi quickstart](/agents/docs/pi#quickstart).
