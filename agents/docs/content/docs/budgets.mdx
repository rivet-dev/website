---
title: "Cost & Token Budgets"
description: "Track what each run costs, cap spending per tenant, and stop an agent that goes over budget."
---

Agents don't enforce a budget on their own. Each model response reports its tokens and cost, so your backend can stop an agent that spends too much.

Put the check in one backend route that every client goes through, and don't give clients direct access to the agent. The check can't live in the agent Actor today, because a user action can't replace Pi's own `prompt`.

- One `tenant` Actor holds the budget for all of a tenant's agents. `spend` is synchronous, so two runs recording at once never lose an update.
- The route refuses to start a run once the tenant has nothing left, and aborts a run when its cost reaches what was left.
- The check runs after each model response, so the response that crosses the line still finishes. Runs that start at the same time can each spend up to what was left. Set the budget a little below your real limit.
- The route records the run's cost from `getSessionStats` before and after the run, which also counts the summaries made during compaction.

For a token budget instead, use `usage.totalTokens` from each `turn_end`, and `tokens.total` from `getSessionStats`.

## What the cost covers

- Cost is in US dollars, calculated from each model's per-million-token prices for input, output, and cached tokens. Models from a custom provider need their own prices.
- It covers model calls only. Sandbox and hosting costs aren't included.
