## What a session is

- One session per agent key.
- Clients connect, disconnect, and reconnect freely. Several clients can watch the same session.

## A turn

- Prompt, model call, tool calls into the sandbox, tool results, reply.
- Every step streams as an event to all connected clients.

## Steering a running turn

- **Steer:** add input to the turn in progress.
- **Follow up:** queue a message for after the turn ends.
- **Cancel:** stop the turn. A command running in the sandbox is killed, not left behind.
- **Timeouts:** per tool command.

## Long-running commands

- agentOS keeps process and terminal output on the VM, so a build or test run survives the client, or even the agent, disconnecting.
- Readers page back through the output with a cursor. Replay is capped by default (1,024 events or 1 MiB per process).

## Compaction

- Manual, or automatic when the context fills.
- What is summarized, and what stays in the stored history.

## Errors and retries

- A model error ends the turn without losing the session.
- Automatic retries.
- After a crash, the session reopens from its last saved entry.

## Sleep and wake

- The agent sleeps when idle. The VM sleeps on its own.
- Waking reloads the session and reconnects to the same VM, with its files intact.
- A config or software change that needs a VM restart shows up in the VM's status.

## Ending a session

- Starting fresh on the same agent versus destroying the agent.
- What happens to the VM and its files, which matters when deleting a user's data.
