## Sessions

- Each agent key has one session.
- Clients can connect, disconnect, and reconnect at any time, and several clients can watch the same session.

## Turns

- A turn takes a prompt through model calls and tool calls in the sandbox until the agent replies.
- Every step streams as an event to all connected clients.

## Steering a turn

- **Steer:** add input to the turn in progress.
- **Follow up:** queue a message to send after the turn ends.
- **Cancel:** stop the turn and kill any command still running in the sandbox.
- **Timeouts:** limit how long each tool command can run.

## Long-running commands

- agentOS keeps process and terminal output on the VM, so a build or test run keeps going if the client or the agent disconnects.
- Output can be read back from any point. By default, the VM keeps up to 1,024 events or 1 MiB per process.

## Compaction

- The agent summarizes older messages when the context fills, or when you ask it to.
- The stored history keeps every entry.

## Errors and retries

- A model error ends the turn but keeps the session.
- Failed model calls are retried automatically.
- After a crash, the session reopens from its last saved entry.

## Sleep and wake

- An idle agent sleeps and frees its memory. The VM sleeps on its own.
- The next prompt wakes the agent, reloads the session, and reconnects to the same VM with its files intact.
- If a config or software change needs a VM restart, the VM's status reports it.

## Ending a session

- Start a new session on the same agent, or destroy the agent.
- Destroying an agent does not delete its VM or files.

- Run code at turn start, on each tool call and result, and at turn end, for approvals, audit logs, and metrics.
